# 오늘의 계획과 작업 메모

매일 업무 기록을 쓰는 사용자가 아침에 할 일을 고르고, 같은 `오늘` 화면에서 진행한 프로젝트와 업무 기록 본문을 바로 작성한다. 캘린더에서는 그날의 계획과 실제 업무를 함께 확인한다.

## 화면과 사용 흐름

- 로그인 영역에 `오늘` 페이지(`/today`)를 추가한다. 데스크톱 헤더와 모바일 드로어는 기존 `AppNav`를 재사용한다. 페이지 날짜는 업무 기록과 동일한 브라우저 로컬 날짜 기준이다.
- `오늘`의 업무 항목은 탭으로 표시한다. 기본 탭은 하나이며 옆의 `+`로 항목을 추가하고 새 탭을 선택한다. 각 탭 안에 `진행한 프로젝트`, 근무시간, `내용`, 연결된 Notion 카드를 둔다. 업무 본문의 입력 영역을 넓게 잡아 오늘 기록을 중심으로 구성한다. 탭을 바꿔도 입력이 유지되며, 키보드로도 선택할 수 있다.
- 새 업무 항목의 카드는 기존 업무 기록의 자동 추천 규칙을 재사용한다. 활성화된 요일별 기본 카드는 고정 시간으로 적용하고, 이전 업무에서 이어지는 카드에는 남은 시간을 자동 배분한다. 저장된 초안이나 확정본을 불러오면 저장된 연결을 그대로 유지한다. 이미 사용자가 편집한 항목에 늦은 추천 응답으로 카드를 다시 넣지 않는다.
- 연결 카드 아래 `+ 카드` 버튼을 누르면 기존 카드 선택 팝업을 연다. 선택한 카드는 현재 업무 탭에 바로 연결하고 같은 업무 안의 중복을 막는다. 같은 날 다른 업무 항목에는 같은 카드를 연결할 수 있다. 기존 `NotionCardLinkSection`과 선택기, 추천·배분 로직을 재사용한다.
- 연결한 카드에는 배분 시간을 입력할 수 있다. 기존 `allocationMode`와 `allocatedHours` 규칙을 재사용해 빈 시간은 자동 배분하고 직접 입력한 시간은 수동 배분한다. 수동 배분 후 남은 근무시간을 자동 카드에 나눈다. 배분 합계는 해당 업무 근무시간을 넘을 수 없다. 입력이 미완성이거나 초과한 상태도 초안으로 보존하고, 확정할 때 오류가 있는 탭으로 안내한다.
- 입력이 잠시 멈추면 미완성 항목과 카드 선택을 포함해 날짜별 업무 초안을 자동 저장한다. `임시 저장 중`, `임시 저장됨`, `실패` 상태를 표시한다. `업무 기록 확정`을 누를 때 기존 날짜 단위 검증·저장 경로로 같은 날의 업무 항목을 저장한다. 그날 확정한 기록도 다시 불러와 수정할 수 있고, 편집 대상 밖의 업무·휴가 항목을 보존한다.
- 카드 후보는 팝업에서 검색하고 추가한다. 하루 메모와 별도의 일반 할 일 입력은 이번 화면에서 제외한다.
- 카드별 메모는 Notion 원본에 보이는 방식을 검토한다. 아래의 `Notion 카드 메모` 절에서 옵션과 권장 흐름을 정리한다.
- 오른쪽 캘린더 미리보기는 모든 탭의 프로젝트·근무시간·본문·연결 카드별 배분 시간과 총 근무시간을 보여준다. 현재 선택한 탭과 관계없이 작성 중인 전체 초안을 즉시 요약한다. `업무 기록 확정`은 하루 전체 항목을 확정한다. 실제 업무 캘린더에서는 임시본과 확정 기록의 표시 상태를 구분하며, 집계는 확정 기록을 기준으로 한다.

## 디자인 기준

[HTML 와이어프레임](../../today-wireframe.html)은 화면 배치와 입력 흐름의 참고 자료다. 구현에는 `globals.css`의 테마, `AppNav`, `@timesheet/ui`의 버튼과 입력 컴포넌트, 기존 업무 기록 상세 패널을 사용한다. 라이트 테마는 슬레이트 배경과 흰 패널, 다크 테마는 기존 설정의 표면색을 따른다. 데스크톱은 왼쪽 입력 영역과 오른쪽 미리보기를 두고, `lg` 미만은 한 열로 배치한다. Notion 연결이 없거나 조회에 실패해도 프로젝트와 업무 본문 입력을 사용할 수 있다.

## 저장과 캘린더 반영

- 업무 초안에 각 업무 항목의 프로젝트, 근무시간, 본문, 카드 연결과 배분 시간을 함께 저장한다. 자동 저장 성공 응답 후 `임시 저장됨`을 표시한다. 이동하거나 날짜를 바꿀 때 저장 중인 입력을 처리하고 실패한 입력은 재시도할 수 있게 유지한다.
- HTML 와이어프레임은 현재 탭의 메모리에서만 값을 사용해 미리보기에 즉시 반영한다. 브라우저 저장소나 서버와 연결되어 있지 않아 새로고침하면 예시로 초기화된다.
- 임시본은 aJam 서버 SQLite에 사용자·날짜별로 보관한다. 새로고침하거나 다시 로그인해도 이어서 작성할 수 있다. 확정 전에는 기존 업무 기록과 근무시간, 작성률, 리마인더, AI 정리, 내보내기에 영향을 주지 않는다. 이미 확정한 날을 편집 중이면 이전 확정본이 계속 표시된다.
- `업무 기록 확정`이 성공하면 기존 업무 기록이 갱신되고 해당 초안이 정리된다. 확정 실패 시 초안은 유지한다. 동시에 다른 탭에서 같은 날짜의 확정본을 바꿨다면 기존 변경을 조용히 덮어쓰지 않도록 확인한다. 늦게 도착한 자동 저장 요청이 이미 확정한 초안을 되살리지 않아야 한다.
- Notion 연결은 기존 캐시의 카드 식별자를 사용한다. 카드가 후보에서 빠지더라도 이미 추가한 항목은 제목과 원본 링크를 계속 확인할 수 있다. 확정 시 각 업무 초안의 카드 연결과 시간을 해당 `TimesheetEntry` 연결 데이터에 함께 반영한다.
- 캘린더는 aJam의 기존 월간 업무 캘린더를 사용한다. 외부 캘린더 동기화, 별도 완료 상태나 이월은 첫 버전 범위 밖이다.

## Notion 카드 메모

- 업무 본문 입력칸은 약 75px 높이로 시작하고 사용자가 늘릴 수 있게 한다. 연결 카드 한 장을 좌우 두 열로 배치한다. 연결 해제 `×`는 카드 왼쪽 상단에 작게 둔다. 왼쪽 열은 제목, 상태·카테고리·자동 연결 출처, 시간과 배분 상태로 구성한다. 오른쪽 댓글 영역은 작성자·시각, 전체 댓글, 되돌리기, `새로 추가`, `업데이트`를 상단 한 줄에 모으고 바로 아래에 72px 높이의 편집기를 둔다. 메타데이터가 길면 말줄임하되 원문을 확인할 수 있게 한다. 좁은 모바일 화면에서는 두 열을 위아래로 쌓는다.
- 마지막 댓글은 조회 가능한 댓글 중 생성 시각이 가장 최근인 댓글이다. 텍스트박스에서 바로 고쳐 업데이트하거나 새 댓글로 추가한다. 다른 작성자의 댓글에는 업데이트를 비활성화하고 새 댓글로 이어 쓰는 기능을 제공한다. 댓글이 없으면 빈 입력창에서 새로 작성한다. 입력 중 댓글 조회가 갱신되어도 작성 중인 내용을 보존하고, 업데이트는 편집을 시작한 댓글을 대상으로 한다. `되돌리기`는 입력을 최신 저장 댓글로 복원한다. 조회 중·실패·댓글 없음 상태를 구분한다.
- 댓글 팝업에는 작성자, 작성 시각과 본문을 보여준다. aJam 연결이 작성한 댓글에는 `수정`과 `삭제`를 제공한다. 다른 작성자의 댓글은 읽을 수 있다. 새 입력은 `Notion에 게시`한다. `수정`을 누르면 기존 내용을 입력창에 불러오고 `업데이트`와 `새 댓글로 추가`를 함께 보여준다. 업데이트는 선택한 댓글을 수정하고, 새 댓글로 추가는 기존 댓글을 보존하며 입력 내용을 새 댓글로 게시한다. 게시·수정·삭제 성공 후 모든 업무 탭의 같은 카드에서 댓글과 마지막 댓글 미리보기를 갱신한다. 카드 연결을 해제해도 Notion 댓글은 보존한다. HTML은 생성·수정·삭제의 예시 동작만 제공한다.
- 목록 조회 API는 미해결 댓글을 반환한다. 해결된 댓글까지 포함한 전체 이력 제공 범위는 별도 확인이 필요하다. [댓글 목록 조회](https://developers.notion.com/reference/list-comments)
- ‘오늘’에서 새로 게시하는 댓글은 로그인한 aJam 사용자의 현재 `username`을 Notion 댓글의 표시 이름으로 저장한다. Notion 페이지와 aJam 이력에서 이 이름을 사용한다. 게시와 수정·삭제 권한에는 기존 Notion 연결을 사용하며, 사용자별 OAuth 연결은 필요 없다. [댓글 표시 이름](https://developers.notion.com/reference/comment-display-name)
- 댓글 API는 생성·조회·수정·삭제를 제공한다. 수정과 삭제는 해당 연결이 생성한 댓글에만 허용된다. 사용자가 Notion에서 직접 작성했거나 다른 연결이 작성한 기존 댓글은 조회 대상으로 두고, aJam 연결이 작성한 댓글에 수정·삭제 동작을 제공한다. 댓글 읽기와 쓰기 capability가 필요하다. [댓글 조회](https://developers.notion.com/reference/list-comments) · [수정 제한](https://developers.notion.com/reference/update-a-comment) · [삭제 제한](https://developers.notion.com/reference/delete-a-comment)
- **페이지 댓글을 우선 제안한다.** aJam의 연결된 카드에서 `Notion에 댓글 남기기`를 눌러 작성하고 전송하면, 해당 카드의 페이지 댓글과 Notion DB의 댓글 아이콘에서 읽을 수 있다. 댓글 쓰기 권한이 필요하다. 입력과 전송을 구분하고, 업무 임시 저장과 확정은 댓글을 발행하지 않는다. 전송 전 입력은 유지하고 성공한 댓글의 원본은 Notion에 둔다. 응답을 받지 못한 전송은 중복 게시 가능성이 있어 자동 재전송하지 않는다. [댓글 작성 API](https://developers.notion.com/reference/create-a-comment) · [Notion DB 댓글](https://www.notion.com/help/comments-mentions-and-reminders)
- **텍스트 속성**은 Notion DB 표의 열이나 카드에 메모 문구 자체를 보여주고 싶을 때 적합하다. 예를 들어 `최근 작업 메모` 속성을 쓸 수 있다. 기존 값의 수정·덮어쓰기 규칙이 필요하고, 날짜별 메모 이력을 남기는 용도라면 댓글이 더 자연스럽다. [페이지 속성 수정 API](https://developers.notion.com/reference/patch-page) · [Notion DB 속성](https://www.notion.com/help/database-properties)
- **페이지 본문 블록**은 내용이 길거나 작업 이력을 카드 본문에 문서처럼 누적하고 싶을 때 적합하다. DB에서 내용을 읽으려면 해당 카드를 열어야 한다. [본문 블록 추가 API](https://developers.notion.com/reference/patch-block-children)

## 독립 검증 기준

1. 데스크톱과 모바일 메뉴에서 `오늘`에 진입할 수 있고, 앱의 라이트·다크 테마에서 입력과 상태를 읽을 수 있다.
2. 프로젝트·본문과 연결 카드를 입력한다. 임시 저장 완료 후 새로고침하고 동일한 항목과 배분 시간이 복원되는지 확인한다.
3. 새 항목은 기존 자동 추천을 적용하고, 저장된 항목은 연결을 유지하는지 확인한다. `+ 카드` 팝업에서 현재 탭에 카드를 추가하고 중복을 막는지, 자동·수동 배분과 초과 안내가 동작하는지 확인한다.
4. 같은 날 업무 항목 두 개에 다른 프로젝트·근무시간·본문·카드를 입력한다. 미완성 초안이 새로고침 후 복원되고, 확정 전에는 기존 기록과 집계가 유지되는지 확인한다. 확정 후 캘린더에서 항목과 연결 카드가 각각 보이며, 기존 업무·휴가 항목이 보존되는지 확인한다.
5. 구현 결과를 받은 Codex가 변경 diff와 읽기·쓰기·캘린더 표시 경로를 직접 검토하고, Antigravity가 보고한 검증 결과와 별개로 GO / NO-GO를 판단한다. 빌드는 사용자 요청이 있을 때 실행한다.
6. 기본 업무 탭 하나에서 시작해 `+`로 두 번째 탭을 만들고 전환한다. 각 탭의 프로젝트·본문·카드·배분 시간이 독립적으로 유지되고, 오른쪽 전체 요약에 두 탭이 모두 표시되는지 확인한다.
7. 댓글 팝업에서 미해결 댓글을 조회하고 aJam 연결이 작성한 댓글만 수정·삭제할 수 있는지 확인한다. 게시 실패 시 입력을 보존하며, 탭과 업무 초안 저장은 댓글을 자동 게시하지 않아야 한다.
8. 카드 오른쪽 텍스트박스에서 마지막 댓글을 직접 수정하고 업데이트하거나 새 댓글로 추가한다. 업데이트는 댓글 수를 유지하고 새로 추가는 이전 댓글을 보존하는지, 마지막 댓글 삭제 후에는 그 이전 댓글이 모든 탭에 표시되는지 확인한다. 다른 탭이나 팝업에서 댓글을 갱신해도 편집 중 입력이 보존되어야 한다.
