# 휴가 유형 이름 일괄 변경 설계

## 범위

휴가 화면의 `휴가 유형` 목록에서 이름을 누르면 선택한 연도에 저장된 같은 이름의 휴가를 한 번에 새 이름으로 변경한다. 다른 연도의 휴가는 변경하지 않는다.

화면에서 공백 이름은 `휴가`로 정규화되어 같은 그룹에 표시되므로, 저장값이 공백인 휴가와 실제 이름이 `휴가`인 휴가도 함께 변경한다. 새 이름이 기존 유형 이름과 같으면 두 그룹을 합친다. 휴가 시간, 상태, 날짜와 업무 기록은 그대로 유지한다.

## 사용자 인터페이스

- 휴가 유형 이름을 접근 가능한 버튼으로 표시한다.
- 이름을 누르면 해당 행 아래에 현재 이름이 채워진 작은 편집 영역을 연다.
- 편집 영역은 이름 입력, `취소`, `변경` 버튼과 저장 상태 또는 오류 메시지를 제공한다.
- 빈 이름은 저장할 수 없다.
- 저장 중에는 중복 제출을 막고, 성공하면 편집 영역을 닫은 뒤 갱신된 연도 데이터를 반영한다.
- 이름 변경과 연도 이동은 동시에 실행하지 않아 이전 연도의 응답이 새 연도 화면을 덮지 않게 한다.
- 기존 색상 원 클릭 편집과 이름 클릭 편집은 서로 독립적으로 동작한다.

## 데이터 흐름

1. `VacationSummaryPanel`이 기존 이름과 새 이름을 워크스페이스 콜백에 전달한다.
2. `VacationYearWorkspace`가 선택한 연도와 이름을 서버 액션에 전달한다.
3. 서버 액션은 세션 사용자, 연도, 기존 이름, 새 이름을 검증한다.
4. DB 저장 함수가 선택 연도의 날짜 범위 안에서 정규화된 기존 이름이 일치하는 사용자의 `TimesheetEntry`와 레거시 `Vacation` 행을 한 트랜잭션으로 갱신한다.
5. 서버 액션이 해당 연도 데이터를 다시 불러와 반환한다.
6. 워크스페이스가 화면 상태를 교체하고 휴가, 타임시트, AI 요약, 프로젝트 화면에 갱신 이벤트를 알린다.

휴가 유형 색상 설정은 기존 결정대로 이름 변경 시 이동하지 않는다. 새 이름에 저장된 색상 설정이 있으면 그것을 사용하고, 없으면 자동 색상을 사용한다.

## 오류 처리

- 연도는 기존 `2000`~`2100` 범위 검증을 재사용한다.
- 기존 이름은 DB 후보를 공유 TypeScript 정규화 함수로 비교해 화면과 동일하게 Unicode 공백까지 처리하고, 새 이름은 앞뒤 공백을 제거한 뒤 빈 값이면 거부한다.
- 일치하는 휴가가 없으면 오류로 처리해 오래된 화면 상태에서의 무의미한 성공을 막는다.
- DB 갱신은 트랜잭션으로 실행해 두 저장 경로 중 하나만 변경되는 상태를 방지한다.
- 클라이언트는 실패 시 편집 영역을 유지하고 오류 메시지를 표시한다.

## 검증

- DB 테스트에서 선택 연도만 변경되는지, 공백 이름과 `휴가` 이름이 함께 변경되는지, 다른 사용자 데이터가 유지되는지 확인한다.
- 기존 이름과 새 이름의 입력 검증을 확인한다.
- 관련 패키지 테스트와 타입 검사를 실행한다.
- 프로젝트 지침에 따라 빌드는 실행하지 않는다.

## 제외 범위

- 모든 연도에 걸친 이름 변경
- 이름 변경 이력 또는 실행 취소
- 별도 휴가 유형 엔터티 도입
- 기존 색상 설정의 자동 이전
